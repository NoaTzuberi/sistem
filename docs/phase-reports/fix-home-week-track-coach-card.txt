Fix — Home: week track + coach card (match docs/design/trainee-home-b.html)
=========================================================================

Summary
-------
- Week track: each lane now has one look, chosen in code (homeDisplay `laneLook`): done = filled with the
  workout's color · today (not done) = ink · planned = white with a 2px ring in its color · missed = soft column,
  faint date, a small dot in its color at the bottom · rest = a hairline. Today keeps the pulsing pink dot
  whether done or not, so today + done = filled + dot. Why it looked wrong before: missed and planned days were
  both a white column with a thin ring (they read as empty outlines), and "today" was drawn over "done".
- The lane logic + the selected day live in a new hook `useWeekTrack` (today is selected by default). The day line
  now reads "מתוכנן · N תרגילים" for planned days. Tapping the day line opens that workout, as before.
- Coach card: ink avatar with the coach's initials (her name now comes with GET /plans/week as `coach: { name }`;
  the nutrition plan's coach is the fallback). The pink dot shows only when something is unread. Her name is in
  Karantina 22px, with the time beside it. The message is 15px / 1.5, cut after 4 whole lines with "עוד" to
  expand: no "…" and no word cut in half. The section head "COACH · מהמאמנת" sits above the card, like the
  other Home sections.
- Quick replies (owner decision in this session): "👍 תודה!" is shown under a real message. It sends her coach an
  in-app notification (new type `coach_note_thanks`, one per note) and then reads "✓ נשלח". "תשובה" stays hidden
  until trainee → coach messaging exists. The pink-soft "week ready" chip still shows only for an unread
  "plan published".

API
---
- GET /api/plans/week: new field `coach: { name } | null` (her coach's name only).
- POST /api/notifications/thanks { note: 'plan' | 'nutrition' } → 204 (trainee only; 400 bad note; 404 no such
  note / no coach). The server finds the note itself (this week's published plan with notes, or her newest
  nutrition version with an intro) and her coach; dedupeKey `coach_note_thanks:<noteId>`, so repeat taps never
  notify twice. No schema change beyond the new notification type id in the enum.
